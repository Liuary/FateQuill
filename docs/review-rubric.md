# 评审 rubric（人读权威文档）

> 版本：**1.0.0**（代码常量 `REVIEW_RUBRIC_VERSION = "1.0.0"`，与 `src/orchestration/review/rubric.ts` 一致）
> 载体：本文件为**人读权威文档**；LLM prompt 内联同一 rubric 的**精简版**（由 `buildReviewSystemPrompt()` 生成），两者须同步演进。

## 1. 分档（`RUBRIC_BANDS`）

| 区间   | 档位   | 说明                                                        |
| ------ | ------ | ----------------------------------------------------------- |
| 0–59   | 不合格 | 存在硬伤（逻辑断裂 / 设定冲突 / 违规 / 严重套话），建议重写 |
| 60–79  | 合格   | 基本达标，尚有明显可改进项                                  |
| 80–89  | 良     | 良好，仅少量可改进项                                        |
| 90–100 | 优     | 优秀，几乎无明显问题                                        |

## 2. 四维子维度（`RUBRICS`）

| 维度   | id           | 评估方式                  | 子维度                                    |
| ------ | ------------ | ------------------------- | ----------------------------------------- |
| 剧情   | `plot`       | LLM-as-judge              | 逻辑连贯 / 冲突推进 / 节奏 / 伏笔呼应     |
| 世界观 | `worldview`  | LLM-as-judge              | 设定自洽 / 术语一致 / 环境可信            |
| 合规   | `compliance` | **规则引擎**（词表/正则） | 涉政 / 色情 / 暴力 / 广告 / 价值观        |
| 真人感 | `humanity`   | LLM-as-judge              | 套话密度 / 句式单调 / 情感空洞 / 信息密度 |

## 3. 声明

- **重写质量以反馈项改善为准**：评估反馈（`reasons` / `findings`）用于指导**下一轮生成**；重写是否更优，以对应反馈项是否改善衡量，而非单看分值波动。
- **LLM 评审温度 = 0**：三个 LLM 维严格以 `temperature = 0` 调用（`createLlmJudgeEvaluator` 默认值），以求可复现的判定。
- **合规低分仅人工裁决**：合规维命中规则即给出扣分与 `findings.hits`，**不触发自动重写**，由人工复核裁决。
- **词表覆盖范围有限**：`compliance-rules.ts` 的内置词表为示意性初始集，需随规范演进更新（版本常量 `COMPLIANCE_RULES_VERSION`）。
- **降级不抛穿**：JSON 解析 / 调用失败经 `evaluateWithFallback` 有限重试后降级为默认分（`DEGRADED_SCORE = 60`）并标注「判定失败」。
