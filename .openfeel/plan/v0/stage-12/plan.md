## 技术约束（本阶段适用，定稿）

### 全自动运行机制（定稿，修订 REV-001）
- **每环节自动决策规则表**：

  | 环节 | 自动决策规则 |
  |------|--------------|
  | 推演 | 大纲约束下**多温度择优**（复用 stage-08，取加权总分最高分支） |
  | 生成 | 按大纲 + 前置章上下文单次生成（复用 stage-05 装配） |
  | 审查 | 四维阈值（复用 stage-06 `passThreshold`） |
  | 重写 | **≤ N 轮（默认 2，可配）**，注入审查反馈（复用 stage-06 回路） |
  | 仍不达标 | **标记「降级收录」（`degraded`）+ 记录原因**，不阻塞续跑 |
  | 归档 | 每章完成后**自动一致性抽取**（复用 stage-11，候选按「自动确认」或待人工按配置） |

- **冲突策略（解决「无人值守」×「用户裁决」核心矛盾）**：
  - **默认「暂停 + 通知」**（保留用户终裁决）；
  - 用户**显式授权开关**「**自动标记 `ignored` 继续**」——冲突按 `ignored` 落 `conflict_record`（**留痕可审计**）。
  - 两条路径**均留痕**；「自动忽略」仅为**用户显式授权**后的行为（不违背「建议非结论」）。
- **熔断三层**：① **预算上限**（`estimateCost` 累计 token/金额）；② **连续失败/低分章节计数**（连续 ≥ K 章不达标）；③ **总章数上限**。任一触发 → **即停并出报告**（含已产出/降级/冲突统计）。
- **断点持久化（必须有，可续跑）**：**迁移 v6**（`autopilot_run` + `autopilot_chapter`），流水线状态**落库**（对照 stage-08 方案 A 会话内存局限——无人值守**必须可续**）；中断后重启可续跑。
- **可判定验收**：给定 **≥3 章大纲** → 无人值守产出 **≥3 章** → 每章 `score ≥ passThreshold`（或标记 `degraded`）+ **全程零人工交互断言**（mock/真机各一）。

## 风险与备注
- **无人值守失控**：预算/连续失败/章数**三层熔断**兜底；冲突默认暂停；「自动忽略」仅显式授权。
- **历法依赖**：大六壬手动月将起步，**不引入历法库**（C-08）；自动历法留后续（体积/许可待评估）。
- **术数数据体量**：大六壬文本体量 > 六十四卦；来源/许可审慎（公有领域白文，今人断语不引入）。
- **发布验证成本**：跨平台打包/签名成本高；v0.6 聚焦 Windows nsis，其余平台显式声明。
- **英文遗漏**：以**键完整性测试**防回归，豁免清单显式化，避免中英混杂。
- **收官依赖外部条件**：真实 Key / GUI / 签名证书等人工协验项**不可由 AI 替代**，如实标注、不伪造；统一协验批次闭合后 M1~M6 方可标定。
