## 技术约束（本阶段适用，定稿）

### 克制收敛机制（定稿，修订 REV-001）——两层收敛
- **① 生成期约束注入**：设定卡 / 大纲 / 硬约束经 **stage-05 装配链**注入推演 prompt（复用 `ChapterPromptInput`；**推演指令为 user 段**，约束进 system 段）。
- **② 产出期偏离标注（可判定判据）**：以**设定卡实体/关键约束的覆盖检查**为主判据（走向卡引用的 `settingCardIds` 覆盖率 vs 本轮注入的设定卡集），**可选**复用 stage-06 评审管线加「贴合度」评估。
- **③「削弱」操作语义**：**排序降权 + UI 显式标注**（**不过滤、不删除**，保持可对比）。
- **④「克制」语义**：发散度由**温度集**决定；收敛器**不强制改写**走向，仅降权/标注。
- **⑤ 终选权 = 用户裁决**：对比 UI 主导；自动收敛**仅辅助排序**。
- **可判定验收**：注入后推演 prompt **含设定卡内容**（单测断言）；对**预构造偏离样本**，收敛器输出偏离标注且该分支**排序下降**（单测断言）。

### 推演契约定稿（定稿，修订 REV-002）
- **温度集**：默认 **`{0.3, 0.7, 1.1}`**；UI 可增删数量与调值；持久化 `localStorage['fatequill.exploration.temperatures']`。
- **per-provider 温度归一**：各 provider 温度范围差异经 **clamp** 处理；**被 clamp 的分支在 UI 显式标注**（避免语义漂移）。
- **同模型多温度 vs 跨模型**：首版定 **同模型多温度**；跨模型**留待用户拍板**（见「待用户拍板」）。
- **输入装配**：复用 stage-05 装配（设定卡/前文上下文）+ 用户「走向意向」输入。
- **输出形态**：结构化 **「走向卡」`{ summary: string; keyTurns: string[]; settingCardIds: number[] }`**（走向摘要 + 关键转折 + 引用的设定卡 id）。
- **落点**：推演引擎 `src/orchestration/exploration/`；UI `src/features/exploration/`。
- **可判定验收**：mock provider 断言 **N 个分支并行调用、各携带指定温度、聚合与完成顺序无关（乱序完成仍正确归位）**。

### 持久化与落地（定稿，修订 REV-003）——方案 A（最小）
- **推演分支 = 会话内存**（`explorationStore`，独立 `create()`；**不落库**，关闭即弃）；V0.3 **不新增迁移**（不建 v5；复看需求出现时再迁移）。
- **采纳落地（双路径）**：
  - **主路径「新建下一章草稿」**：经 `chapter.create` **新建后一章**并写入以该走向卡生成的内容，**不改当前章 DB**（**不适用 `Ctrl+Z` 撤销**）。
  - **次路径「替换当前章」**：经 stage-04 **`EditorController.replaceContent(html)`** 整章替换，执行前需**用户确认 + 强制入池快照**（可选登记入 stage-06 版本池复看），**单条撤销**（**`Ctrl+Z` 语义归此路径**）。
- **丢弃**：内存快照清空（**无残留**定义 = 该分支不出现在 `explorationStore` 快照、无悬挂引用）。
- **可判定验收**：**主路径**采纳后**新章存在且当前章内容不变**（断言）；**次路径**采纳前经确认 + 生成快照，采纳后 `chapter` 内容变更且**单次 `Ctrl+Z` 恢复采纳前正文**（复用 stage-04 语义断言）；丢弃后 `explorationStore` 快照**无该分支**（断言）。

### 并行工程细节（定稿，修订 REV-004）
- **并行度默认上限 = 3**，用户可调；超限**排队**。
- **成本预估**：`分支数 × 输出 token 上限`（默认输出上限常量），**启动前显示**（可判定）。
- **部分结果可用**：**≥1 分支成功即可对比/采纳**；失败分支显示原因 + **单独重试**入口；`abort` **全部停止**。
- **可判定验收**：mock 断言单分支 reject 时其余分支正常聚合、失败分支可单独重试、abort 全部停止。

### 结构与可判定（定稿，修订 REV-006）
- **C-07**：任务表含「交付物路径 + 可判定验证标准」两列。
- **C-11（i18n）**：启用 **`exploration`** 命名空间（对比 UI/配置文案双语，zh-CN/en）。
- **IPC 影响**：**无新增 Rust 命令**——推演复用 stage-03 `http_stream` 中继；各分支**非流式收口**（聚合为走向卡后回传）。
- **文档回写**：`docs/structure.md`（`src/orchestration/exploration/` 与 `src/features/exploration/` 落点）、`manual/index.md`（归档阶段登记 exploration 模块）。

## 风险与备注
- **成本放大**：N 分支并行 = N × 生成 Token；启动前成本预估 + 并行度上限（默认 3）缓解；用户可控。
- **温度跨 provider 语义**：clamp 仅解决范围越界，**敏感度差异无法完全归一**（分支质量可能不等价）——UI 标注 + 用户裁决兜底。
- **收敛判据局限**：覆盖检查为**近似判据**（基于 `settingCardIds` 引用），不能保证剧情级贴合；v0.3 以「辅助排序 + 人工裁决」为限，不追求自动终判。
- **存储方案 A 取舍**：关闭后未采纳分支丢失（v0.3 接受）；复看需求出现时按 stage-02 迁移纪律补 v5。
- **走向卡 vs 正文**：走向卡为**摘要式**（非正文片段），降低 token 与落库复杂度；正文生成仍归 stage-05。
