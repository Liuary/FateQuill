# op-001：多温度并行推演编排、契约与走向意向入口（T1）

- **阶段**：v0.3.0-stage-08
- **状态**：done
- **前置**：无（首个 op；stage-03 引擎、stage-05 生成闭环已归档）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标
定稿并落地多温度并行推演契约与编排：温度集（默认 `{0.3,0.7,1.1}`、可调/持久化）+ **per-provider 温度 clamp（越界分支标注）** + 输入装配（复用 stage-05 `ChapterPromptInput`）+ **走向卡 `{summary,keyTurns,settingCardIds}` 输出**；交付走向意向输入 UI 与 `explorationStore`（会话内存分支容器）。

## 定稿约定（plan v2 REV-002）
- 温度集默认 `{0.3,0.7,1.1}`；UI 可增删/调值；持久化 `localStorage['fatequill.exploration.temperatures']`。
- **per-provider clamp**：各 provider 温度范围差异经 clamp；**被 clamp 分支 UI 显式标注**（`effectiveTemperature` 与 `clamped`）。
- **首版同模型多温度**（跨模型留待后续）。
- **输入** = stage-05 装配（设定卡/前文）+ 用户「走向意向」；**推演指令为 user 段、约束进 system 段**。
- **输出** = 走向卡 `{ summary: string; keyTurns: string[]; settingCardIds: number[] }`；非流式收口（聚合后解析 JSON）。
- **落点**：`src/orchestration/exploration/`（引擎）+ `src/features/exploration/`（UI）；**无新增 IPC**（复用 `http_stream`）。
- **可判定验收**：mock provider 断言 **N 分支并行、各携带指定温度、乱序完成正确归位**；被 clamp 分支被标注；走向卡结构完整。
