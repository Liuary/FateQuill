# v0.1.0-stage-05 详细计划：单 Agent 章节生成 + 设定卡（v0.1 闭环）

## 归属版本
v0.1（最小可用闭环）—— 本阶段是 v0.1 的收口与验收终点。

## 目标
打通「创作 → 生成 → 落地」闭环：单一 Agent 依据上下文与设定卡生成章节内容，流式增量插入编辑器，生成期间编辑器不重渲染。

## 对应核心目的
- 目的 1：让创作者能实际产出章节文本。
- 目的 2：为后续「真人感审查/去 AI 味规避」提供生成入口与对照样本。

## 前置依赖
v0.1.0-stage-03（引擎）、v0.1.0-stage-04（编辑器）

## 技术约束（本阶段适用）
- 流式：增量追加 + 节流重渲染（C-02）。
- 状态隔离：生成态独立 store，**生成时编辑器零重渲染**（C-03）；仅「插入到正文」为显式提交动作。
- 上下文装配：包含当前章、前情提要、相关设定卡；须有长度上限与裁剪策略。
- 单 Agent、单模型（v0.1 默认；多模型并行留待后续版本）。

## 任务表

| # | 任务 | 交付物 | 验收标准 | 依赖 |
|---|------|--------|----------|------|
| T1 | 生成请求装配（上下文 + 提示词） | 上下文构建器 + 提示模板 | 输入作品/章/设定→生成请求 payload；超长有裁剪（测试） | stage-03,04 |
| T2 | 流式生成面板（独立 store） | 生成态 store + 预览面板，含停止/重试 | 生成时 editorStore 快照不变；停止可中断 | T1 |
| T3 | 增量追加与节流重渲染 | 节流器接入预览渲染 | 重渲染按 ≥50ms 合并；预览连续无闪烁 | T2 |
| T4 | 插入正文（显式提交） | 「插入到章节」动作 | 点击后内容按光标/末尾插入并持久化 | T2,T3 |
| T5 | 设定卡 CRUD | 设定卡列表/编辑器 UI + 持久化 | 增删改查可用且重启保留；可被生成上下文引用 | stage-02 |
| T6 | 闭环端到端验证 | E2E 用例 + 手测脚本 | 完整走通「建作品→建卷章→生成→插入→存设定卡→重启不丢」 | T1~T5 |

## 阶段验收标准（DoD，即 M1）
- [ ] **M1**：新建作品 → 建卷/章 → 编辑正文 → AI 生成一章并流式插入 → 保存设定卡 → 重启后数据完好。
- [ ] 生成期间编辑器组件重渲染次数 = 0（可测）（C-03）。
- [ ] 流式增量 + 节流重渲染可测（C-02）。
- [ ] 设定卡可持久化并被生成引用。
- [ ] 生成可中断、可重试，异常有提示、不残留半态。

## 风险与备注
- 上下文裁剪策略影响生成质量，需在 skill/提示模板中版本化，便于后续「去 AI 味 skill 库」注入（stage-07）。
- 编辑器与生成态若耦合过深将阻碍后续并行推演（stage-08），本阶段须以事件/订阅解耦。
