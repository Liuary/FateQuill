# v0.1.0-stage-04 详细计划：编辑器基础（Tiptap 章节文档 + 大纲树）

## 归属版本
v0.1（最小可用闭环）

## 目标
交付高性能的章节编辑器与卷章大纲树，落实「按章节分文档」与「长文不卡顿」的硬性要求。

## 对应核心目的
- 目的 1：创作者的主创作界面。
- 目的 2：为人味修改提供顺手的编辑体验（后续标注/对比的基础）。

## 前置依赖
v0.1.0-stage-01、v0.1.0-stage-02

## 技术约束（本阶段适用）
- 编辑器：Tiptap；**一章一文档实例**（C-01），切换章节时销毁/重建而非累加。
- 支持所见即所得 + Markdown 输入/序列化。
- 自动保存：防抖保存到 stage-02 存储层，避免丢失。
- 长文性能：5000 字章节输入延迟 < 16ms；切章无明显卡顿。

## 任务表

| # | 任务 | 交付物 | 验收标准 | 依赖 |
|---|------|--------|----------|------|
| T1 | 集成 Tiptap 基础编辑器 | 编辑区组件 + 基础扩展（段落/标题/粗斜体等） | 可输入并渲染富文本；内容可序列化 | stage-01 |
| T2 | 章节文档模型与切换 | 一章一实例的加载/卸载逻辑 | 切换章节内容正确、无串档；内存不随章数线性增长 | T1,stage-02 |
| T3 | Markdown 支持 | 输入规则 / 导入导出 | 常见 Markdown 语法正确往返（有测试） | T1 |
| T4 | 卷 → 章 大纲树 | 左侧树组件 + 增删改/拖拽排序 | 结构操作同步持久化，顺序正确 | stage-02 |
| T5 | 自动保存与状态提示 | 防抖保存 + 保存状态指示 | 编辑后自动落库；断章不丢（测试/手测） | T2 |
| T6 | 长文性能优化与验证 | 编辑器态 store（Zustand）+ 性能用例 | 5000 字输入延迟 < 16ms（基准记录） | T2 |

## 阶段验收标准（DoD）
- [ ] 单章 5000 字输入延迟 < 16ms（有可复现基准）（C-01）。
- [ ] 切换章节时旧文档实例被销毁，无内容串档。
- [ ] 卷/章 增删改与排序持久化正确。
- [ ] 自动保存可靠，异常退出后可恢复最近编辑。
- [ ] Markdown 往返测试通过。

## 风险与备注
- Tiptap JSON 与本阶段存储格式需固化，并保证与 stage-02 的 `Chapter.content` 兼容。
- 编辑器态 store 与后续生成态 store 必须分离（为 C-03 铺路）。
