# op-010：修复切章未 flush 导致的数据丢失（BUG-001）(fix)

- **阶段**：v0.1.0-stage-04
- **状态**：pending
- **前置**：op-003（T2）、op-005（T4）、op-006（T5）、op-008（T7）的产出（均已执行）
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **关联缺陷**：`BUG-001`（high）——切章不 flush，防抖窗口内切章导致前一章编辑永久丢失

## 目标
接线自动保存的 **flush**：所有切章入口在旧编辑器实例销毁前 **`await flush()`** 落库；flush 失败**阻断切章并提示**；补齐 DoD 第 5 条要求的「编辑 → <800ms 内切章 → 前一章不丢」可判定集成测试；并排查其他「实例销毁前需 flush」入口。

## 缺陷根因（取证）
- `ChapterEditor` 暴露 `onFlushReady`（L44-46）但**无消费方**；`WorkspaceLayout` 渲染 `<ChapterEditor chapterId={currentChapterId} />` **未传** `onFlushReady`；`OutlineTree.selectChapter`（L101-103）直接 `setCurrentChapter(id)`，**切换前未 flush**。
- 切章时 `RichTextEditor`（`key=chapterId`）卸载、Tiptap 实例销毁；残留防抖计时器回调旧闭包 `editor.getHTML()` 失败 → 置脏重试经 `enqueueRef` 指向**当前（新）章** → 旧章编辑永久丢失。
- `useAutoSave.test.ts` 用例①仅直调 `hook.flush()`，**未覆盖真实切章路径**。

## 与既有 op 的关系（编号不冲突）
- 本 op **仅修改 op-003/op-005/op-006/op-008 的产出文件**（`useAutoSave.ts` / `ChapterEditor.tsx` / `WorkspaceLayout.tsx` / `OutlineTree.tsx` + 新测试 + i18n），不新增编号冲突；op-001~009 保持已执行状态。
- 修复后须经 **openfeel-executor** 执行、**openfeel-feel-tester** 复验 BUG-001。

## 实施步骤
- [ ] 1. `useAutoSave.ts`：`flush` 返回**成功态**并加固计时器
  ```ts
  // flush 语义：无脏内容→true；保存成功→true；保存失败→false（仍置脏 + 重试，不静默丢弃）
  const flush = useCallback(async (): Promise<boolean> => {
    if (timer.current) { clearTimeout(timer.current); timer.current = null; }
    if (!dirtyRef.current) return true;
    let ok = false;
    chainRef.current = chainRef.current.then(async () => {
      // ...（沿用串行化 enqueueSave 逻辑：执行时重新取 editor.getHTML()；成功 ok=true，失败 ok=false + 置脏/重试）
    });
    await chainRef.current;
    return ok;
  }, [/* deps */]);
  ```
  - **计时器章号守卫**（防销毁实例旧闭包误写当前章）：新增 `chapterIdRef = useRef(chapterId)`（随 `chapterId` 更新）；防抖回调与重试回调执行前校验 `chapterIdRef.current === capturedChapterId`，不等则**跳过**（避免误写当前活动章）。
  - `useFlushOnClose` 的 `globalFlush` 类型同步为 `() => Promise<boolean>`（await 结果忽略布尔）。
- [ ] 2. `ChapterEditor.tsx`：`onFlushReady?: (flush: () => Promise<boolean>) => void`（类型对齐）；继续在 effect 中透传。
- [ ] 3. `WorkspaceLayout.tsx`：接线 + 守卫式切章
  ```tsx
  const flushRef = useRef<() => Promise<boolean>>(() => Promise.resolve(true));
  const setCurrentChapter = useEditorStore((s) => s.setCurrentChapter);
  const setSaveStatus = useEditorStore((s) => s.setSaveStatus);

  /** 唯一合法切章入口：先 flush 旧章，成功才切；失败阻断并提示（BUG-001 修复核心） */
  const requestSelectChapter = useCallback(async (id: number) => {
    if (id === currentChapterId) return;
    const ok = await flushRef.current();       // 旧实例销毁前的同步 flush
    if (!ok) { setSaveStatus("error"); return; } // 落库失败：阻断切章（重试成功后用户可再切）
    setCurrentChapter(id);
  }, [currentChapterId, setCurrentChapter, setSaveStatus]);

  <ChapterEditor chapterId={currentChapterId} onFlushReady={(f) => { flushRef.current = f; }} />
  <OutlineTree novelId={currentNovelId} selectedChapterId={currentChapterId} onSelectChapter={requestSelectChapter} />
  ```
  > 说明：`flushRef.current` 始终指向「当前渲染的 ChapterEditor 的 flush」，其闭包绑定**当前 `chapterId`/editor**，在 `setCurrentChapter` 之前调用即保存旧章。
- [ ] 4. `OutlineTree.tsx`：移除直连 store；所有切章入口统一走注入的守卫
  - 新增 prop `onSelectChapter: (id: number) => void`（**不再**内部 `useEditorStore.setCurrentChapter`）；
  - `selectChapter(id)` → 调 `props.onSelectChapter(id)`；`OutlineVolumeNode`/`OutlineChapterNode` 已使用 `onSelectChapter`，透传即可（**未来键盘切换等入口亦必须走此 prop**）。
- [ ] 5. 数据完整性加固（同源风险，排查所得）
  - **重命名当前章防陈旧覆盖**：`renameChapter` 现以 outline 中的**旧 `chapter.content`** 调 `update`，会覆盖编辑器未保存内容 → 改为：先 `await flushRef.current()`（经父层传入或事件回传）再 `get_chapter` 取最新内容后 `update({title:新标题, content:最新内容, ...})`；或仅当非当前章时直接改标题。
  - **删除当前章/卷**：`removeChapter`/`removeVolume` 若含当前章，先 flush（或显式确认丢弃）再删除。
  - **切书**：`setCurrentNovel` 目前仅默认选择；若后续加入切书入口，须先 flush 并清 `currentChapterId`（本 op 在代码注释声明该约束）。
  - **关闭窗口**：确认 `useFlushOnClose` 的 `onCloseRequested → globalFlush → destroy` 已覆盖（核对 `globalFlush` 指向当前章 flush，无需改动）。
- [ ] 6. i18n：`editor:{switchBlockedBySaveError}`（zh-CN/en 同步），用于切章被阻断时的状态/提示。
- [ ] 7. 新增 DoD 集成测试 `src/features/editor/chapter-switch-flush.test.tsx`（jsdom + mock `@tauri-apps/api/core`）
  - mock：`list_novels`→1 书、`list_volumes`→1 卷、`list_chapters`→[第1章,第2章]、`get_chapter`→对应 HTML、`update_chapter`→记录调用；
  - **主用例（DoD 第 5 条）**：渲染 `WorkspaceLayout` → 选中第 1 章 → `editor.commands.insertContent("新增片段")` → **<800ms 内**点击第 2 章 → 断言 `update_chapter` 收到 `{ id: 1, content 含「新增片段」 }`（旧章先落库）→ 且随后加载第 2 章内容正确；
  - **失败阻断用例**：mock `update_chapter` reject（`DB_LOCKED`）→ 点击切章 → 断言 **未切章**（`editorStore.currentChapterId` 仍为第 1 章）+ `saveStatus==='error'`；
  - **（可选）重命名不覆盖**：重命名当前章后断言 `update_chapter` 的 `content` 含最新编辑。
