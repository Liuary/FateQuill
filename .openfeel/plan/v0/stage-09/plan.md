# v0.3.0-stage-09 详细计划：易经卦象系统（六十四卦 + 爻变）

> 修订：v2（2026-10-10，依据 REV-v0.3.0-stage-09 的 5 条审查意见按 stage-07/08 v2 范式重写）。

## 归属版本
v0.3（创造引导）

## 目标
将易经六十四卦与爻变建模为**可选**的剧情引导系统，为多温度推演提供方向性输入，并映射角色宿命。
**可选可关**：不成为创作流程强制前置，**关闭时零副作用**。**大六壬显式排除**（留 stage-12）。

## 对应核心目的
- 目的 1：为剧情走向与角色命运提供有结构的、非随机的引导。
- 目的 2：术数引导属于「人类创作传统」，可增加人味与作者性，间接服务去 AI 味。

## 技术约束（本阶段适用，定稿）

### 易经数据定稿（定稿，修订 REV-001）
- **数据来源**：**公有领域《周易》经文白文**（卦辞 + 爻辞），**不含需授权的今人译注**；来源与校对口径登记 **`docs/iching-data.md`**（版本化）。
- **格式与落点**：`src/data/iching/`（TS 结构化常量 + zod 校验）；**只读静态资源，无新迁移**；打包体积影响纳入 `docs/build-size-report.md`（复用 stage-08 T6 口径）。
- **校验规则（清单化，启动期 + 测试期）**：① 卦数 = **64**；② 每卦 **6 爻**（合计 **384**）；③ 卦名唯一；④ 上下卦组合覆盖 **8×8**；⑤ **King Wen 卦序连续 1~64**；⑥ **二进制↔卦名映射自洽**。
- **可判定验收**：校验测试断言上述**全部规则** + 抽样卦（乾 / 坤 / 既济）**字段完整性**。

### 算法定稿（定稿，修订 REV-002）
- **变爻规则**：**采用朱熹《易学启蒙》变爻规则**（0 爻变看本卦卦辞；1 爻变看本卦变爻辞；2 爻变看本卦二变爻辞以上爻为主；3 爻变看本卦与之卦卦辞；4 爻变看之卦二不变爻辞以下爻为主；5 爻变看之卦不变爻辞；6 爻变看之卦卦辞）；纯函数 `deriveHexagram(lines: Line[]) → { benGua, zhiGua, changingLines }`。
- **起卦方式（v0.3 范围）**：
  - **随机** = **可注入随机源**（支持种子复现，测试确定性）；
  - **手动** = 直接指定卦 + 可选指定变爻（摇卦模拟）；
  - **时间起卦（农历/干支）→ 降级推迟**：v0.3 **不引入历法依赖**（C-08），入口不呈现；列为**可选增强**（见「待用户拍板」）。
- **可判定验收**：mock 随机源断言本卦/之卦/变爻正确；朱熹多爻变规则**抽样断言**（含 0/1/2/6 爻变）；随机/手动入口均可独立触发。

### 卦象引导契约与 stage-08 衔接（定稿，修订 REV-003）
- **引导卡结构**：`{ hexagramName, judgmentDigest, changingLineReadings, plotHints, fateHints }`。
- **注入点**：开启时卦象引导**并入推演 system 约束段**——`buildExplorationOptions` 增**可选参数 `hexagramGuide?`**，**缺省完全不影响**（与 stage-05 `skills?` / stage-08 同范式，向后兼容）。
- **与克制收敛联动**：卦象提示定位为「**走向意向的结构化来源之一**」，**不进入** `converge` 的设定卡覆盖判据（**设定卡约束仍为最高优先**）；偏离仍按 stage-08 规则标注（卦象**不覆盖**设定卡硬约束）。
- **关闭零副作用（可判定）**：关闭时 `buildExplorationOptions` 输出与**基线快照逐字段一致**、卦象模块**零调用**；开启时 system 段含卦象引导文本且 `converge` 行为不变。

### 角色宿命线（定稿，修订 REV-004）
- **绑定存储**：v0.3 收敛为「**会话内存 + 挂 `setting_card`**」——宿命提示产出后由用户**手动写入角色设定卡**（复用既有 `setting_card` 编辑链路，**零迁移**）；「绑定」= 起卦时选定 `character`/设定卡作为产出目标，产出后入卡（**持久化免费获得且用户可控**）。
- **宿命形态**：v0.3 = **一次性提示卡**（**不做跨章自动持续约束**，避免角色命运漂移治理问题——留待后续版本）。
- **与 converge 关系**：宿命提示写入设定卡后**自然进入**下一轮注入与覆盖判据（复用 stage-08 机制，零新增逻辑）。
- **可判定验收**：选定角色/设定卡 → 产出宿命提示卡 → **写入设定卡成功**（断言）；**未开启卦象时入口不可见**（断言）。

### 可选可关落地设计（定稿，修订 REV-005⑤）
- **开关位置**：**推演面板内开关**（`src/features/exploration/` 内，不新增独立设置页）；**缺省关闭**。
- 持久化 `localStorage['fatequill.iching.enabled']`；不成为任何流程的强制前置（关闭即完全旁路）。

### 结构与可判定（定稿，修订 REV-005）
- **C-07**：任务表含「交付物路径 + 可判定验证标准」两列。
- **C-11（i18n）**：启用 **`iching`** 命名空间（起卦 UI/引导卡文案双语 zh-CN/en；**卦辞经文本身不译**）。
- **IPC 影响**：**无新增 Rust 命令**——卦象数据为**前端静态资源**（`src/data/iching/`），不落库；在 `docs/ipc.md` 声明。
- **文档回写**：`docs/iching-data.md`（新增）、`docs/structure.md`（`src/data/iching/`、`src/orchestration/iching/`、`src/features/exploration/` 开关落点）、`docs/build-size-report.md`（数据体积）、`manual/index.md`（归档阶段登记 iching 模块）。

## 风险与备注
- **术数主观性**：须以「**引导而非断言**」定位，避免产品争议；卦象仅辅助排序，**不覆盖设定卡硬约束**。
- **数据体量**：64 卦辞 + 384 爻辞为数千行结构化文本，是本阶段最大单体工作量；来源与校对需审慎（登记口径）。
- **多爻变流派分歧**：v0.3 明确采用朱熹规则，**不追求各流派兼容**（避免范围膨胀）。
- **时间起卦推迟**：农历/干支转换依赖未引入（C-08）；如需，后续以「轻量农历算法 + 体积评估」再议。
- **宿命线形态**：v0.3 为一次性提示，**无跨章持续约束**——避免角色命运漂移治理复杂度。
- **数据与前序复用**：卦象引导与 stage-05 `skills?`、stage-08 走向意向同为「装配层可选注入」，保持同范式降低耦合。

## 待用户拍板（建议默认值）
1. **变爻流派**：建议默认**朱熹《易学启蒙》规则**（纯函数、可单测）。
