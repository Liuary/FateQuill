# op-007：修复易经开关独立 hook 状态导致运行时切换不生效（BUG-001）(fix)

- **阶段**：v0.3.0-stage-09
- **状态**：pending
- **前置**：op-005（T5 接入/开关）等已执行产出
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **关联缺陷**：`BUG-001`（medium）——`useIChingEnabled()` 在 `ExplorationPanel` 与 `useExploration` 各持独立 `useState`，运行时切换开关不生效（`buildGuideCard`/`renderGuideText` 零调用），DoD 第 4 条真实 UI 路径失败

## 目标
将「启用易经推演」开关改为**单例共享状态**：`ichingEnabled` 提升到 `explorationStore`（含 `localStorage` 持久化），`ExplorationPanel`（开关 UI）与 `useExploration`（装配注入）**共用同一 store 状态**，使运行时切换**即时生效**（无需重载），关闭仍零副作用。

## 缺陷根因（取证）
- `useIChingEnabled()`（`useState` 本地态）被 `ExplorationPanel`（L45）与 `useExploration`（L41）**各调用一次** → 两份互不相通的 state；写入 `localStorage` 后另一实例**不重读**。
- 运行时点击开关 → 装配侧实例仍为挂载时值 → `hexagramGuide` 恒 `undefined` → 引导不注入；反向（挂载时已开、运行关闭）引导仍注入。
- 现有单测因**挂载前预置 `localStorage`** 而通过，掩盖运行时路径。

## 方案（状态共享 —— 采纳 store 单例）
- **单例载体 = `explorationStore`**（复用既有 store，**零新增依赖**）：新增 `ichingEnabled: boolean`（初值 `readIChingEnabled()`）与 `setIChingEnabled(value)`（写 store + `localStorage['fatequill.iching.enabled']`）。
- **采纳理由**：`explorationStore` 已是推演域的会话单例，`casting` 等跨组件状态已在其中（REV-007 先例）；store 订阅天然驱动 `ExplorationPanel` 与 `useExploration` **同步重渲染**，运行时切换即时生效；比 Context/storage 事件更简单且可测。
- `useIChingEnabled()` **保留为薄封装**（读/写 store 选择器），调用方签名不变（`{ enabled, setEnabled }`）。

## 涉及文件/目录
- 修改：`src/store/explorationStore.ts`（`ichingEnabled` + `setIChingEnabled` + 持久化）
- 修改：`src/features/exploration/useIChingEnabled.ts`（改为读/写 store 单例；保留 API）
- 修改：`src/features/exploration/useExploration.ts`（`ichingEnabled` 取自 store 选择器）
- 修改：`src/features/exploration/ExplorationPanel.tsx`（同一来源）
- 测试：`src/features/exploration/ExplorationPanel.test.tsx`（**运行时切换新用例** + 预置方式改 store 动作）、`src/features/exploration/useExploration.test.ts`（单例共享/注入时机）

  ```ts
  export { ICHING_ENABLED_STORAGE_KEY } from "@/store/explorationStore";

  export function useIChingEnabled(): { enabled: boolean; setEnabled: (v: boolean) => void } {
    const enabled = useExplorationStore((s) => s.ichingEnabled);

    return { enabled, setEnabled };
  }
  ```
