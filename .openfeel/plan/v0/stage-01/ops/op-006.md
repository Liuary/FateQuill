## 目标
建立 GitHub Actions CI：runner = `windows-latest`，范围为 `pnpm lint` + Vitest + `pnpm build`（含 tsc 类型检查）+ `cargo check` + `cargo test`；**不含 `tauri bundle`（移至 stage-12）**。提交 PR / push 触发并全绿。

## 前置说明
- 阶段计划定稿：CI runner = `windows-latest`（与开发平台一致，避免 Linux 的 `libwebkit2gtk` 等系统依赖）。
- 验收依赖 op-009：远程仓库就绪并完成推送后，才能观察到 workflow run 结果（human 协验，`gh` 未安装）。
- CI **不安装** Tauri 打包依赖，不做 `tauri build`/`bundle`。

## 涉及文件/目录
- 新增：`.github/workflows/ci.yml`

## 实施步骤
- [ ] 1. 新建 `.github/workflows/ci.yml`
  ```yaml
  name: CI

  on:
    push:
      branches: ["main"]
    pull_request:

  jobs:
    ci:
      runs-on: windows-latest
      env:
        RUST_BACKTRACE: "1"
      steps:
        - uses: actions/checkout@v4

        - name: Setup pnpm
          uses: pnpm/action-setup@v4
          with:
            version: 12.10.1

        - name: Setup Node
          uses: actions/setup-node@v4
          with:
            node-version: "24"
            cache: pnpm

        - name: Setup Rust
          uses: dtolnay/rust-toolchain@stable

        - name: Cache Rust
          uses: Swatinem/rust-cache@v2
          with:
            workspaces: src-tauri

        - name: Install dependencies
          run: pnpm install --frozen-lockfile

        - name: Lint
          run: pnpm lint

        - name: Frontend tests
          run: pnpm test

        - name: Frontend build (tsc + vite)
          run: pnpm build

        - name: Rust check
          run: cargo check --manifest-path src-tauri/Cargo.toml

        - name: Rust tests
          run: cargo test --manifest-path src-tauri/Cargo.toml
  ```
  > 注：Node 显式固定 `"24"`（对应 `package.json.engines.node = ">=22"` 与实际 v24.18.1）。`actions/setup-node@v4` 的 `node-version-file` 对 `package.json` 的 `engines` 支持不稳定，故不采用。
- [ ] 2. 本地语法/结构自查（尽力而为）
  ```powershell
  Test-Path .github/workflows/ci.yml
  Select-String .github/workflows/ci.yml -Pattern "windows-latest","frozen-lockfile","tauri"
  ```
  预期：`windows-latest` 与 `frozen-lockfile` 命中；**不含 `tauri`**（打包步骤）。
- [ ] 3. 提交并推送（**REV-009**；前置：op-001~op-005、op-007、op-008 均已各自提交，op-009 已完成首次远程推送）
  ```powershell
  # 前置校验：暂存前工作区应仅剩待提交的 ci.yml（其余 op 变更应已提交）
  git status --porcelain
  git add -A
  git commit -m "ci: add windows-latest CI (T6)"
  git push
  ```
  > 按 REV-009 建议，提交**全部待提交变更**（而非仅 `ci.yml`）；若暂存前 `git status --porcelain` 含非 `.github/workflows/ci.yml` 的条目，说明前置 op 未提交，须先补齐再执行本步。
- [ ] 4. （人工/协验）在 GitHub 观察 workflow run 结果
  - 打开仓库 Actions 页，确认 `CI` workflow 被触发且全绿。
  - 或（若后续安装 `gh`）：`gh run list --workflow ci.yml` / `gh run watch`。
  - 若在 PR 上验收：新建分支 → 提交 → 开 PR → 确认 CI 全绿。
