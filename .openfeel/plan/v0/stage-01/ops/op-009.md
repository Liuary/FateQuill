# op-009：配置 GitHub 仓库托管与远程推送（T9）

- **阶段**：v0.1.0-stage-01
- **状态**：pending
- **前置**：op-001（本地仓库与首次提交）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标
将本地仓库关联到 GitHub `FateQuill` 远程仓库并成功推送，使 `git remote -v` 指向 FateQuill 且 `git push` 可用（T6 的 CI 验收依赖本 op）。

## 人工前置（必须由用户完成，不可由 AI 代劳）
- `gh`（GitHub CLI）**未安装**，默认路径为**用户手动创建仓库**：
  1. 用户在 GitHub 创建**空仓库** `FateQuill`（不要初始化 README/.gitignore/LICENSE，避免与本地冲突）。
  2. 用户提供并授权推送方式：
     - HTTPS：Personal Access Token（`repo` 权限），或
     - SSH：本地已配置的 SSH key。
  3. 用户告知远程 URL，形如 `https://github.com/<owner>/FateQuill.git` 或 `git@github.com:<owner>/FateQuill.git`。
- **备选路径（需用户明确授权）**：安装 `gh` CLI 后，由 AI 执行 `gh repo create FateQuill --public --source=. --remote=origin --push`。

## 涉及文件/目录
- 修改：`.git/config`（新增 `remote.origin`）
- 无新增源码文件

## 实施步骤
- [ ] 1. 确认本地仓库与提交已就绪（op-001 完成）
  ```powershell
  git status
  git log --oneline
  ```
- [ ] 2. （等待用户反馈）获取 GitHub 仓库 URL 与推送授权
  - 记录 URL：`$REMOTE_URL = "https://github.com/<owner>/FateQuill.git"`
- [ ] 3. 配置远程并确保分支为 main
  ```powershell
  git remote remove origin 2>$null   # 若已存在旧 origin，先清理
  git remote add origin $REMOTE_URL
  git branch -M main
  ```
- [ ] 4. 推送前完整性校验（**REV-009②**）
  ```powershell
  git status --porcelain   # 预期输出为空：所有 op 变更均已提交
  git log --oneline        # 预期含 op-001~op-005/007/008 的提交（T1~T5、T7、T8）
  ```
  > 若 `git status --porcelain` 非空，须先补齐提交再推送；否则远程将缺少 Tailwind/shadcn/Vitest/i18n/IPC 等实现代码，T6「CI 全绿」必挂。
- [ ] 5. 推送
  ```powershell
  git push -u origin main
  ```
  > 若 HTTPS 首次推送提示鉴权失败：由用户配置凭证（Git Credential Manager 或 `git config credential.helper`）。
- [ ] 6. 校验
  ```powershell
  git remote -v
  git status
  git log --oneline -1
  ```
