## 目标
落地**四级分级模型**（`main`/`dark`/`short`/`temp`）与**迁移 v5**：`setting_card.tier` 列 + `conflict_record` 表；仓储与 IPC 支持 tier 读写/过滤；**迁移幂等**（Docker-free SQLite 断言：表数 **9→10**、`tier` 列存在）。

## 技术依据（plan v2 定稿）
- 四级定义（判定标准 / 生命周期 / 冲突严格度）：
  | tier | 语义 | 生命周期 | 冲突严格度 |
  |------|------|----------|------------|
  | `main` | 贯穿全书核心约定 | 长期；转正后永久 | 硬约束必须遵守 |
  | `dark` | 隐藏设定（未揭示） | 长期隐藏；揭晓后可转主线 | 硬约束，**不注入正文** |
  | `short` | 近期章节有效 | 近章生效；可转正/过期 | 软约束 |
  | `temp` | 一次性/局部细节 | 可丢弃/过期 | 仅提示 |
- 与 `SettingCard.kind` **正交**（`kind`=内容类型，`tier`=叙事层级；**不扩 kind 值域**）。
- 持久化：**迁移 v5** `ALTER TABLE setting_card ADD COLUMN tier ... DEFAULT 'short'`（**短线保守默认**）——tier 过滤在 **SQL 层**。
- **实测基线**：`src-tauri/migrations/` 现有 v1~v4；`migrations.rs` 测试 `migration_creates_schema` 断言 **9 表**、`migration_is_idempotent` 断言 `_sqlx_migrations`=**4**；`setting_card` 命令 L98-127（无 tier）。

## 困难点与决策
- **SQLite `ADD COLUMN` 带 `CHECK`**：SQLite 允许 `ADD COLUMN` 携带列级 `CHECK`（禁止的是 PRIMARY KEY/UNIQUE 与无默认的 NOT NULL）。**决策**：保留 `CHECK` 以在 DB 层兜底四级枚举；若 `cargo test` 报语法不支持，**退化为应用层校验 + 无 CHECK**（备选），并在 op 修正记录注明。
