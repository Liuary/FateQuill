## 二、核心结论与经验

1. **计划详度前置拦截（REV-001~008）**：v1 计划凭空缺版本表 / 存储格式定稿 / 性能方法学 / editorStore 边界等关键约定，审查官逐条要求补全后重写至 v2（详度对齐 stage-02/03）。**代价**：计划返工一轮。教训：编辑器类阶段须在计划中先定稿「存储格式 + 版本表 + 验收方法学」三件套。
2. **撤销会话合并：从错误机制到内建方案（REV-009 high）**：op-009 原方案用 `addToHistory:false` + 会话末 `delete+insert 同文本` 提交，审查官指出该事务**对文档净变化为零** → `Ctrl+Z` 不移除整段生成，且会误删会话前内容。修正为 prosemirror-history 内建 **`newGroupDelay=5000` 分组合并**（流式插入恒入历史），语义正确且实现更简。
3. **IME 监听落点纠偏（REV-010）**：`editor.on("compositionstart")` 非 Tiptap 事件（编辑器事件总线不含 DOM composition），IME 排队为死代码。改监听 `editor.view.dom` 的 DOM 事件并补 `dispose()`。
4. **保存并发竞态（REV-011）**：`saveNow` 无互斥，慢写旧内容可覆盖新写。修正为 `chainRef` 串行 promise 链 + 执行时重取 `getHTML()` 最新优先。
5. **切章 × 防抖数据丢失（BUG-001 high，测试阶段暴露）**：T5 自测仅直调 `hook.flush()`，未覆盖真实切章路径；测试官用有状态 mock 最小复现「<800ms 切章丢第 1 章」，触发 `test_failed → scheme_pending` 修复闭环（op-010）。修正后经测试官独立复验通过并关闭。**这是「自测替代真实路径」导致验收缺口被测试阶段兜住的典型案例。**
6. **修复方案审查的价值**：op-010 审查官核验 4 点修复方向 + 同类入口排查（renameChapter 陈旧覆盖 / 删除当前章卷 / 切书约束 / 关窗覆盖）+ 时序细节（`ok` 变量经 chainRef 赋值、chapterIdRef 守卫语义），确认无新增 REV。
