## 二、核心结论与经验

1. **核心机制必须定稿且可判定（REV-001 high）**：plan v1 自认「克制收敛不可判定」——四大语义（注入什么/判据/削弱操作/终选权）全缺。定稿**两层收敛**：① 生成期约束注入（复用 stage-05 装配，约束进 system / intent 进 user）；② 产出期设定卡覆盖检查（可判定判据）+ **削弱 = 降权 + 标注**（不过滤不删）；③ **终选权 = 用户裁决**（自动收敛仅辅助排序）。
2. **推演契约四项定稿（REV-002 high）**：温度集 `{0.3,0.7,1.1}` + UI 可调/持久化；**per-provider clamp** + 被 clamp 分支标注；首版**同模型多温度**（跨模型留拍板）；输出结构化**走向卡** `{summary,keyTurns,settingCardIds}`；验收含「乱序完成正确归位」断言。
3. **持久化方案 A（最小）（REV-003 medium）**：分支=会话内存（`explorationStore`，不落库、不新增迁移 v5）；采纳复用 stage-04 `replaceContent`（单撤销）/ 可选版本池；丢弃=快照清空无残留；风险节诚实声明「关闭丢失，v0.3 接受」。
4. **并行工程量化（REV-004 medium）**：并行度上限默认 3 + 排队；**成本预估含输入侧 N 倍**（REV-008①：装配上下文每分支全量重复发送）；部分结果可用（≥1 成功即可对比/采纳）+ 失败分支单独重试 + abort 全停。
5. **遗留处置显式化（REV-005 low）**：stage-05 REV-015（chunk 评估）→ 列入 T6；v0.2 4 项人工协验 BLOCKED 保持跟踪、不阻塞、闭合后 M2 达成。
6. **C-07 可判定性恢复（REV-006 low）**：任务表补「交付物路径 + 可判定验收」两列 + i18n/IPC/文档回写声明 + 待拍板/schemer 清单。
7. **采纳数据安全网（REV-007 high, blocking）**：原「整章替换当前章 + 版本池登记仅可选」叠加 `useAutoSave` 自动保存 → 误触采纳致原正文 **DB 级永久丢失**。改**双路径**：① 主路径「**新建下一章草稿**」（`chapter.create`，不改当前章 → 根除丢失，语义更准，不适用 `Ctrl+Z`）；② 次路径「替换当前章」升级**确认 + 替换前强制入池快照（必做）** + 单撤销；两路径均加确认门。
8. **走向卡幻觉引用防护**：审查非阻塞提示 → op-003 收敛器加**存在性校验**（过滤无效 id + 记入 `invalidSettingCardIds` + 计为偏离）。
9. **manualChunks 兑现 REV-015（T6）**：Vite 8/rolldown 兼容该字段；实测入口 **909.94→356.57 kB raw（−60.8%）** / gzip **−61.0%**，总增量 ≈0、`>500 kB` 警告消除 → **采纳**（`docs/build-size-report.md`）。
10. **「功能无入口」防范复验**：推演 UI 挂第三栏「推演」tab + 采纳经 `BranchCompare → useAdoptBranch` 生产接线，收口以生产调用非零 rg 断言核验（沿用 stage-07 教训）。
