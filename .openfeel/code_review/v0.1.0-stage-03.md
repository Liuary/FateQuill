## 二、核心结论与经验

1. **架构裁决是本阶段最大价值点（REV-001 high）**：审查官提前拦截「Vercel AI SDK × C-04 Rust 侧网络」的结构性矛盾（AI SDK 为 TS 库、provider 默认 `fetch` 直连，引入即违反 C-04/C-05）。经用户确认采纳 **ADR-001**：v0.1 不引入 `ai` 包，数据面定为 Rust 侧 provider 无关 SSE 中继 + 前端自研适配器，Key 零下发。计划审查前置化避免了执行期结构性返工。
2. **契约真实对齐优于强转**（REV-011 high）：适配器 `httpStream as unknown as StreamTransport` 双重强转掩盖了 `requestId` 必填缺参——真实路径必失败、回放测试全绿掩盖。修正为「`requestId` 可选 + `httpStream` 内部生成 + `StreamTransport` 真实签名对齐」，由 tsc 编译期保证，缺陷掩盖面消除。
3. **数据完整性边界（REV-012）**：relay 仅按 `\n\n` 切块，对 CRLF provider 静默丢数据。增加跨块 `carry_cr` 状态机归一化 + 末块冲刷，并补 CRLF 测试样本。
4. **验证命令系统性笔误（REV-010）**：9 处 `rg "\|"` 实为字面竖线而非 alternation，全部「命中」验证假阴性；统一改 `rg -n -e A -e B`（防复发见 `kb/patterns.md`）。
5. **Key 零下发闭环**：AUTH_DENYLIST 丢弃前端授权头 + keyring 注入 + `err_event` 脱敏 + roundtrip/哨兵断言，四层守护；无 `keyring_get` 命令。
6. **工具化判定**：新增 Provider 的「核心零改动」以 `git diff` 范围口径判定；`rg` 系列（无 `ai` / 无 `fetch` / 无 `as unknown as` / 无 `keyring_get`）作负向门禁。
7. **技术坑沉淀**：native-tls 规避 aws-lc-rs、keyring 4 平台后端、Channel vs emit、迁移 v2 纪律 → 见 `kb/troubleshooting.md` / `patterns.md`。
