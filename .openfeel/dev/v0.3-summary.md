|-----------|------|:----:|
| **推演半边**（stage-08） | 同模型多温度并行推演「走向卡」分支 + 克制收敛两层（约束注入 + 偏离标注降权）+ 采纳双路径安全网 + 并发/成本/失败处理 | ✅ 通过（**DoD 10/10**、门禁 6/6、**0 Bug**） |

**结论**：**v0.3 代码层与自动层达成 M3**（两阶段全部归档、端到端链路以自动化测试可判定闭合：`cargo test` 52/52、Vitest 415/415）；**真机与度量层人工协验待办**，闭合后 M3 方可标记完成。
- **「卦象可映射到剧情走向」**：引导卡（`buildGuideCard` → `renderGuideText`）经 stage-08 `buildExplorationOptions.hexagramGuide?` **实时进入推演** system 约束段。
- **「收敛到用户设定」**：由 stage-08 既有机制承接——卦象**不进入** `converge` 的设定卡覆盖判据（`settingCardIds` 不变），设定卡约束仍为最高优先。

| 阶段 | 主题 | 核心交付 | 测试基线 |

**v0.3 架构主线**：把「接下来怎么发展」从单点生成升级为**可选的多分支/卦象引导**，并严守「**引导而非断言**」定位——工具提供方向性输入与结构化来源，终选权与设定卡硬约束始终归用户。

## 三、关键架构与决策（v0.3 落地）

1. **多温度并行推演**：`runExploration` 并行 + `concurrency`（默认 3）+ **索引槽位乱序归位** + 单分支失败置 `error` 不抛穿；per-provider 温度 clamp（越界分支 `effectiveTemperature` + `clamped` 显式标注）；结果 = 结构化**走向卡** `{ summary, keyTurns, settingCardIds }`（非流式收口 + JSON 容错）。
2. **克制收敛两层**：① 生成期——设定卡/关键约束并入 **system 段**（复用 `PROMPT_BUDGET.system`）；② 产出期——`converge` 纯函数以设定卡覆盖检查为主判据（`coverage = |有效引用 ∩ 注入集| / |注入集|`，含**存在性校验**过滤幻觉引用），**仅降权 + 标注、不过滤不删**；终选权归用户。
3. **采纳双路径安全网（REV-007 high）**：主路径「新建下一章草稿」**不改当前章 DB**（根除自动保存覆盖）；次路径「替换当前章」**替换前强制入池快照** + 单条 `Ctrl+Z`；两路径均经**内联二次确认**（取消 → 零副作用）。
4. **易经卦象系统**：数据 `src/data/iching/`（公有领域《周易》白文 + 手写守卫，**无新迁移 / 无新 IPC**）；算法 `src/orchestration/iching/`（纯函数：`deriveHexagram`/`zhuXiReading`/`readingVerses`/`castRandom`/`createSeededRng`/`castManual`/`buildGuideCard`/`renderGuideText`/`buildFateCard`）；UI 与开关 `src/features/exploration/`。
5. **朱熹变爻七情形**：0 本卦卦辞 / 1 本卦变爻辞 / 2 本卦两变爻以**上爻**为主 / 3 本卦与之卦卦辞 / 4 之卦两不变爻以**下爻**为主 / 5 之卦不变爻辞 / 6 之卦卦辞；含「变爻集合 = 两卦 `binary` 差异位」一致性守卫。
6. **引导契约（跨阶段扩展）**：`buildExplorationOptions.hexagramGuide?: { text: string }`——开启且已起卦时并入 system 段；**缺省/空白 → 输出与基线逐字段一致、无空段**，`buildGuideCard`/`renderGuideText` **零调用**；卦象**不进** `converge` 判据。
7. **角色宿命线**：会话内存 + 用户写入 `setting_card`（`kind="fate"`，复用编辑链路，**零迁移**，仅**新建**单一路径）；**一次性提示卡**（不做跨章自动持续约束）；入卡后自然进入下一轮注入与覆盖判据（复用 stage-08 机制，零新增逻辑）。
8. **可选可关**：开关在推演面板内、**缺省关闭**、`localStorage` 持久化；`ichingEnabled` 落 **`explorationStore` 单例**（BUG-001 修复后定稿），开关 UI 与消费侧**同源** → 运行时即时生效；关闭零副作用。
9. **领域算法可测性**：解卦/推导纯函数 + **可注入随机源**（`createSeededRng` 种子复现），把不确定性收敛到单一注入点；数据校验**手写类型守卫**（六规则自定，零依赖）。
10. **无新增依赖 / 无新增 IPC**：stage-09 全程零新增 `package.json` 依赖、零新增 Rust 命令（`git diff ca593b5..HEAD` 相关文件全空）；数据为前端静态资源，随 `orchestration` 分组打包（+30.36 kB）。

## 五、v0.4 衔接建议

1. **多声部主线（M4，stage-10）**：角色 Agent 多声部对话——v0.3 的编排引擎（Provider/Agent/Pipeline 注册表）、装配器、多温度推演、卦象引导均已就绪；「每角色独立 Agent + 旁白/对话分离」可直接复用 `Agent`/`Pipeline` 契约扩展。
2. **设定一致性（M5，stage-11）**：设定分级归档 + 一致性引擎——可复用 stage-09 宿命卡写入设定卡的「入卡即进注入/判据」链路与 stage-08 `converge` 覆盖检查。
3. **术数扩展（M6，stage-12）**：**大六壬**（stage-09 显式排除）+ 全自动创作 + MIT 开源发布（英文版收口）——卦象系统已建立「可选可关 + 静态数据 + 引导契约」范式，大六壬按同范式接入。
4. **去 AI 味深化**：① T6 度量放大到统计显著性验证（真实数据回填后）；② 交叉判断模糊对齐（当前 verbatim 精确交集，接受召回损失）；③ skill 自动归纳（当前需人工参与）。
5. **基础设施补强**：① 评估引入 **tauri-driver**（真实端到端自动化，替代/补充手测）；② 真实 WebView perf 纳入常规回归；③ 采纳快照持久化（REV-009 路线）兑现。
