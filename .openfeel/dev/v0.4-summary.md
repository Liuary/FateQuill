## 一、里程碑状态（M4）

> **M4 判定（大计划 §4 / roadmap）**：主要角色各自独立 Agent 生成台词，旁白与对话可分离创作与合并。

| 半边 / 层 | 内容 | 状态 |
|-----------|------|:----:|
| **多声部编排层**（stage-10） | 每角色独立 Agent（persona 契约）+ 旁白 Agent、旁白/对话分离创作、用户主导轮次、上下文隔离防串味、合并双路径落章、成本/并发、台词评审可选衔接 | ✅ 通过（**DoD 11/11**、门禁 6/6；1 medium Bug 闭环） |
| **真机 / 语义层** | 真实 Key 多声部 E2E / 真机 WebView / 台词评审语义符合度 | ⏳ **3 项人工协验待办（BLOCKED）** |
| **结构判定** | 多声部由「一个 Agent 写全文」升级为「旁白 Agent + 每角色独立 Agent」 | ✅ **结构性目标全部达成** |

**结论**：**v0.4 代码层与自动层达成 M4**——端到端链路以自动化测试可判定闭合（`cargo test` 52/52、Vitest **503/503**、99 文件）；**真机与语义层人工协验待办**，不影响结构判定。
- **「各自独立 Agent 生成台词」**：`buildCharacterAgentPrompt`（persona 完整注入本人 Agent）+ 旁白 Agent（仅 system 差异），persona 注入断言可判定。
- **「旁白与对话可分离创作与合并」**：`dialogueStore` 分离条目（`kind: dialogue|narration`、`orderIndex` 恒连续）+ `assembleDialogueHtml` 保序拼接 + 合并**双路径**（主无损 / 次确认 + 强制快照 + 单撤销）。

**v0.4 架构主线**：把「一个 Agent 写全文」升级为**多声部协作**——旁白与每角色各有独立 Agent（persona 契约），在**上下文隔离（防串味）**前提下分离创作，产物经**安全双路径**合并落章。

## 三、关键架构与决策（v0.4 落地）

1. **角色 Agent + persona 契约（零迁移）**：`character.profile` 为 JSON 文本列（原表为极简占位），最小字段 `{identity,personality,speechStyle,goal,extra,major?}`；`CHARACTER_PROFILE_KEYS`/`normalizeProfile`/`toProfileRecord` 单一来源；`buildCharacterAgentPrompt`（本人 persona 完整注入）；旁白 `buildNarratorAgentPrompt`（仅 system 差异）。
2. **旁白/对话分离创作**：`dialogueStore` 会话内存条目（`kind` + `orderIndex`），旁白与角色台词分别生成、分别编辑；轮次**用户主导**（选中角色 → 生成 → 追加历史 → 可反复）；「导演式自动编排」留待后续。
3. **上下文隔离白名单（防串味，本阶段核心）**：每角色 Agent 输入 = **本人 persona（完整）** + **公共场景** + **公共对话历史**；**不含他人 persona 全文**（仅**公开身份一行摘要**）；场景上下文四构成（设定卡 + 前章末尾/当前章 + 用户场景指令 + 公共对话历史）经 `buildPublicContext` 单源产出；装配层断言「A 秘密 X 不入 B prompt」。
4. **产物与合并**：格式单一规范（`<p class="dialogue|narration">`，样式 CSS 承担）；`assembleDialogueHtml` 按 `orderIndex` 保序 + HTML 转义；**合并双路径**复用 stage-08 REV-007 安全网范式（主「新建下一章草稿」不改当前章 DB / 次「替换当前章」确认 + 强制入池快照 + 单撤销）。
5. **成本 / 并发**：复用 stage-08 `estimateCost`（参与角色数 × 输出上限，**启动前显示**）；`runWithConcurrency`（默认 3，超限排队，乱序归位，单项失败不抛穿）；`selectParticipants({ majorOnly })` 按 `profile.major` 过滤。
6. **台词评审衔接（可选）**：`review-bridge.ts` 对齐 stage-06 `ReviewInput`（**不新增评估器、不改 stage-06 契约**）；「千人一腔」与 stage-06 `humanity`「真人感」**互认**（`docs/review-rubric.md` §4.1）。
7. **与 stage-11 边界**：本阶段只**交付 persona 装配输入契约**；stage-11 的设定分级在该契约之上结构化，**不回改本阶段**（deps.yaml 中 stage-11 反向依赖 stage-10）。
8. **零迁移 / 无 IPC 增量 / 零新增依赖**：复用 `character` 五命令 + `chapter` 命令 + `http_stream`（非流式收口）；`git diff` 对 `src-tauri` 全空。

## 五、v0.5 衔接建议

1. **设定一致性主线（M5，stage-11）**：设定分级归档 + 一致性引擎——**直接建立在 stage-10 交付的 persona 装配输入契约之上**（`CHARACTER_PROFILE_KEYS`/`normalizeProfile`），做结构化供给；可复用 stage-09 宿命卡「入卡即进注入/判据」链路与 stage-08 `converge` 覆盖检查。
2. **多声部深化**：① 台词评审**维度子集**（REV-007）或 UI 勾选；② `registerCharacterAgent` 生产接线统一（底座与 `toCharacterOptions` 二者择一）；③ 前文口径（当前章正文入上下文）与用户确认；④ 「导演式自动编排」可选引入（现为用户主导）。
3. **术数扩展（M6，stage-12）**：**大六壬**（stage-09 显式排除）+ 全自动创作 + MIT 开源发布（英文版收口）——卦象系统已建立「可选可关 + 静态数据 + 引导契约」范式，大六壬按同范式接入。
4. **基础设施补强**：① **采纳/合并快照持久化**（迁移 v5 路线，兑现 stage-08 REV-009）；② 评估引入 **tauri-driver**（真实端到端自动化）；③ 真实 WebView perf 纳入常规回归。
